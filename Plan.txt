🚀 1. The Core Engineering Challenge
We need to take a scanned, non-OCR, multi-page (e.g., 20 pages) PDF exam paper (located in input/[Original_Name].pdf) that contains handwritten/printed math and complex diagrams, and transform it into a publication-quality typeset LaTeX PDF output (output/[Original_Name]_LaTeX_compiled.pdf) with high-resolution extracted figures embedded.
The Absolute Google AI Studio Free Tier Bottleneck (Gemini 3.5 Flash)
•	Daily Request Limit: 19 Requests per 24 hours (strict ceiling).
•	Rate Limits: 5 Requests per minute (RPM) / 250K Input Tokens per minute (TPM).
•	Architectural Solution: A "Cache-First Local Slicing State Machine." The pipeline must log every milestone in a persistent cache/[Original_Name]_state.json file. If a subsequent step (such as local compilation) fails, the program must resume from the cache state instead of repeating previous API transactions.

⚙️ 3. Multi-Phase Execution Pipeline
Phase 1: Preflight & Environment Verification (preflight.py)
•	Check the host platform (Windows, macOS, Linux).
•	Search the system PATH using shutil.which() for pdflatex (or latexmk) and Poppler binaries (pdftoppm). Prompt user with OS-specific install commands if missing.
•	Silently run python pip installations for: google-genai, pdf2image, pillow, pypdf, python-dotenv.
•	Authenticate and validate the Gemini API key. Store keys and paths in a secure config file.
Phase 2: PDF Scan & Coordinate Extraction (extractor.py)
•	Read source file name from input/. Check if cache/[Original_Name]_state.json already contains "extraction_result". If it does, skip this phase!
•	If uncached, upload the source PDF to Google Files API (client.files.upload()).
•	Query gemini-3.5-flash using a strict JSON output schema. In ONE single request, map the layout of all 20 pages. Extract questions, raw text, and relative bounding boxes [ymin, xmin, ymax, xmax] for any diagrams.
•	Throttle execution with a 12-second delay before/after the call to avoid RPM limits.
•	Save result to cache/[Original_Name]_state.json.
Phase 3: Offline Lossless Slicing (processor.py)
•	Run entirely offline (Consumes 0 API requests).
•	Read the cached bounding boxes. Convert the target PDF pages to high-resolution (300 DPI) PIL images in-memory via pdf2image.
•	Crop diagrams losslessly and save to cache/images/ using the original filename layout.
Phase 4: LaTeX Compilation & Self-Correction (compiler.py)
•	Pass structured text and diagram image paths to Gemini to generate the initial LaTeX code. Standardize math notations:

$$Z(s) = \frac{V(s)}{I(s)}$$
•	Compile locally: pdflatex -interaction=nonstopmode -output-directory=output output/[Original_Name]_LaTeX_compiled.tex.
•	Parse compilation logs. If failures are found, extract the log error, send only the broken snippet back to Gemini, patch the file, and re-compile (Max 3 correction loops).
